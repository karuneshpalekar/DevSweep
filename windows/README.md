# DevSweep for Windows

The Windows port of DevSweep. See [PLAN.md](PLAN.md) for the goals, the
accuracy traps and the milestones. This folder holds milestones **M0** (the
solution skeleton, CI, and a spike proving the filesystem primitives every
size and every removal rests on) and **M1** (the filesystem layer and safety:
walker v2, the safety guard, quarantine, Restart Manager blockers, the cleaner
and History; see [M1](#m1-filesystem-layer-and-safety)) and **M2** (the rules
engine, named locations, the installed-apps inventory, the first detectors and
`devsweep scan`; see [M2](#m2-rules-engine-and-inventory)).

Windows 11 (22H2, build 22621) or later, x64.

## Build and test

You need the .NET 10 SDK (`global.json` pins 10.0.100 and rolls forward to
any newer 10.0 feature band).

```powershell
cd windows
dotnet build DevSweep.slnx -c Release
dotnet test tests/DevSweep.Core.Tests -c Release
dotnet test tests/DevSweep.Accuracy -c Release --logger "console;verbosity=detailed"
dotnet publish src/DevSweep.Cli -c Release -r win-x64 -o artifacts/cli   # Native AOT
artifacts\cli\devsweep.exe scan                                         # overview sizes; changes nothing
artifacts\cli\devsweep.exe scan --exact --explain --category packageCaches
artifacts\cli\devsweep.exe scan --json --project-root D:\src > scan.json
artifacts\cli\devsweep.exe rules validate                                # bundled + %LOCALAPPDATA%\DevSweep\Rules
artifacts\cli\devsweep.exe rules validate my-pack.yml
artifacts\cli\devsweep.exe inventory [--json]                            # installed apps, per source
artifacts\cli\devsweep.exe measure $env:USERPROFILE\.nuget\packages
artifacts\cli\devsweep.exe measure C:\some\folder --json --time-limit 30
artifacts\cli\devsweep.exe measure C:\some\folder --no-streams        # faster, no handle per file
artifacts\cli\devsweep.exe quarantine list                              # size and age of each item
artifacts\cli\devsweep.exe quarantine restore <id>
artifacts\cli\devsweep.exe quarantine empty --older-than 30 --yes
artifacts\cli\devsweep.exe history                                      # where every removed item went
artifacts\cli\devsweep.exe history restore <id>
```

The accuracy suite builds its fixtures (hard links, junctions, compressed and
sparse files, denied folders, paths over 260 characters) under
`%TEMP%\DevSweepFixtures` on a real NTFS volume and removes them afterwards.
It runs as a normal user. The two symbolic-link tests skip themselves when the
account may not create symlinks (no Developer Mode and no privilege); junctions
need no privilege.

CI (`.github/workflows/windows.yml`, `windows-latest`, x64) is the build and
test authority: restore, Release build with warnings as errors, both test
projects (TRX results uploaded as an artifact), the accuracy suite a second
time as a freshly created standard user (`eng/run-as-standard-user.ps1`), a
Native AOT publish of the CLI and a smoke run of `devsweep measure`,
`quarantine` and `history`, then `rules validate`, `inventory --json` and
`scan --json` as the administrator and again as the standard user. The scan and
inventory JSON of both runs are uploaded as the `golden-scan-windows-latest`
artifact (the first golden scan, PLAN 6).

Engine conventions: small single-purpose types, Win32 only through CsWin32's
generated `PInvoke` (internal to each assembly), metadata-only file access, no
reflection-based serialisation (the Core project is built with

## Accuracy primitives (the M0 spike)

All in `src/DevSweep.Core/Platform`. Each is proved by tests in
`tests/DevSweep.Accuracy` on the CI runner's NTFS volume.

| Primitive | How | Proved by |
|---|---|---|
| **On-disk size** (`FileInspector`) | `FILE_STANDARD_INFO.AllocationSize` from a handle opened with `FILE_READ_ATTRIBUTES` only; for compressed or sparse files `FILE_COMPRESSION_INFO.CompressedFileSize`; for WOF-compressed files (`compact /exe`, CompactOS) `GetCompressedFileSizeW` through the overlay filter | `AllocationSizeTests`: an ordinary file equals its length rounded up to clusters; an NTFS-compressed 4 MiB text file and a 16 MiB sparse file with a 12 MiB hole report less than their length and exactly what `GetCompressedFileSizeW` reports; a 1 TiB sparse file reports almost nothing; a WOF-compressed file reports its compressed size |
| **File identity and hard links** (`FileIdentity`, `HardLinkLedger`) | Volume serial + 128-bit file ID from `GetFileInformationByHandleEx(FileIdInfo)`, handle opened with `FILE_READ_ATTRIBUTES` and `FILE_FLAG_BACKUP_SEMANTICS \| FILE_FLAG_OPEN_REPARSE_POINT`; files with more than one link are counted once per walk; files whose links are not all inside the walk are reported as shared | `HardLinkTests`: all four names of a file share one identity; a folder holding a file and three hard links to it measures as one file; a link from outside makes the bytes "shared", so freeable = 0 |
| **Walker** (`DirectoryWalker`) | `FindFirstFileExW` (`FindExInfoBasic`, `FIND_FIRST_EX_LARGE_FETCH`) on `\\?\` paths, iterative (no recursion limit); every reparse point is recorded and never entered; size = allocation, deduped by file ID; time limit and cancellation return partial counts with `Complete = false` | `WalkerTests`: junctions (and symlinks where creatable) are listed, not followed, and their targets are not counted; a junction loop terminates; measuring a junction measures the link; a file 15 folders deep (path over 300 characters) is found; zero time limit and cancellation give `Partial`; a folder denied to Everyone counts as `AccessDenied` |
| **Cloud placeholders** (`CloudFiles`) | Classified from directory-entry attributes only: `RECALL_ON_DATA_ACCESS`, `RECALL_ON_OPEN` or `OFFLINE` mean "placeholder" (counted as 0 bytes, never opened); `PINNED`/`UNPINNED` or a cloud reparse tag without those bits mean "synced, local". All handles also use `FILE_FLAG_OPEN_NO_RECALL` | `CloudFilesTests` (unit). Real Cloud Filter fixtures are M1 |
| **Recycle Bin** (`Recycling/RecycleBin`) | Before recycling: no junction or link on the path (`ReparseGuard`), the drive is fixed, the bin is not turned off (policy `NoRecycleFiles`, BitBucket `NukeOnDelete`), the item (larger of logical and on-disk size) fits the limit (policy `RecycleBinSize` or BitBucket `MaxCapacity`). An unknown limit gives `Unknown`, never "can be restored". Recycles with `SHFileOperationW` (`FOF_ALLOWUNDO \| FOF_NO_UI \| FOF_NORECURSEREPARSE`) and checks the item is gone | `RecycleBinTests`: a small file leaves its folder and the bin's item count grows; an item over the limit is "would be permanent" and left alone; a 1 TiB sparse file is never called reversible; recycling a junction removes the link and keeps the target's files; an item reached through a junction is refused |

`WalkResult` carries `Bytes`, `LogicalBytes`, `Files`, `Complete`,
`ReparsePoints`, `SharedLinkBytes`, `CloudPlaceholderCount`, `AccessDenied`,
`Unreadable` and a `SizeConfidence` (`Exact`, `SharedLinks`,
`CloudPlaceholders`, `AccessDenied`, `Partial`; the most serious wins).
`devsweep measure <path> [--json]` prints all of it, laid out for comparison
with Explorer's "Size on disk", `fsutil` and `du -l`.

### Gaps M0 left (all closed in M1)

- Alternate data streams were not counted: walker v2 counts them (`FileStreamInfo`).
- MFT-resident small files: decided and documented (below).
- Reparse-point folders were never entered: cloud-provider folders now are (attributes only); mount points are recorded, not blocked, never crossed.
- Paths of 260+ characters could not be recycled: they go to DevSweep's quarantine.
- One open per file for allocation and ID: listings now come from `FileIdExtdDirectoryInfo` (see the benchmark for what that does and does not buy).

## M1: filesystem layer and safety

Everything below is proved by the accuracy suite on the `windows-latest` runner
(Windows Server, NTFS, 4 KiB clusters), first as the runner's administrator and
then again as a freshly created standard user. Numbers are from CI run
[41805780286](https://github.com/karuneshpalekar/DevSweep/actions/runs/41805780286)
unless noted.

### Walker v2 (`DirectoryWalker`, `DirectoryLister`, `FileMeasurer`)

- Each folder is opened as itself (`FILE_LIST_DIRECTORY`, `FILE_FLAG_OPEN_REPARSE_POINT`,
  `FILE_FLAG_OPEN_NO_RECALL`) and listed with `GetFileInformationByHandleEx(FileIdExtdDirectoryRestartInfo /
  FileIdExtdDirectoryInfo)`: attributes, reparse tag, sizes and the 128-bit file ID for every entry,
  without opening the entries. The handle is checked to still be a folder (not a junction swapped in
  after its parent was listed) before it is listed.
- Where the class is unsupported (FAT, exFAT, some network file systems) the walk falls back to
  `FindFirstFileExW` for the rest of the walk; `WalkResult.Listing` says which was used.
- NTFS directory entries carry no link count, and their size copy is only updated under the name a
  file was written through, so every file still gets one metadata query and the fresh value is used:
  - default (alternate streams counted): one attribute-only handle per file, `FILE_STANDARD_INFO` +
    `FileStreamInfo` (+ `FILE_COMPRESSION_INFO` for compressed or sparse files);
  - `AlternateStreams = false` / `--no-streams`: `NtQueryInformationByName(FileStatInformation)`, no
    handle at all, link count and fresh sizes by name.
- Alternate data streams are added to `Bytes` and reported (`AlternateStreamCount`, `AlternateStreamBytes`).
  The WOF filter's `WofCompressedData` stream is excluded (it is the main stream's data).
- Small MFT-resident files: **decision: report what NTFS reports.** A 100-byte file reports 104 bytes of
  allocation (rounded to 8, held inside its 1 KiB MFT record, no clusters). Explorer's "Size on disk"
  shows 0. Either way it is under one cluster, and deleting it frees no clusters, which is inside the
  freed-space tolerance.
- Cloud-provider folders (cloud reparse tag, not a placeholder) are entered reading attributes only.
  A cloud folder that is itself still a placeholder (not populated) is counted as a placeholder and not
  listed, because listing it would ask the provider to fetch its contents. Every other reparse point
  (junction, symlink, volume mount point, WSL link, app alias, projected FS) is still a hard stop.
- All M0 guarantees hold (all M0 tests unchanged and passing): no reparse traversal, long paths,
  time limit and cancel with `Complete = false`, hard-link dedupe and "shared" detection, `SizeConfidence`.

| Proved by (`WalkerV2Tests`, `SecondVolumeTests`) | Result |
|---|---|
| Mixed tree (hard links inside and to outside, compressed, sparse, junction, ADS, 300+ char path): v2, v2 no-streams, forced fallback and the M0 walker | identical files (7), folders (15), duplicates (1), shared bytes (200,704), reparse points (1); bytes 1,900,560 with streams, 1,826,832 without; difference = the one 70,000-byte stream's 73,728 bytes |
| File with a 1 MiB stream and a 40-byte `Zone.Identifier` | main 4,096 + streams 1,048,616 = 1,052,712 on disk; 4,096 with `--no-streams` |
| 100-byte (MFT-resident) file | 104 bytes from the handle, from the listing walk and by name |
| Hard link written through its other name | walker reports the fresh 2,101,248 bytes (the stale-entry counter stayed 0 on this runner: NTFS had already updated the entry) |
| WOF (`compact /exe:xpress4k`) file | 311,296 bytes in every mode, no stream double count |
| exFAT volume (64 MB VHDX mounted in a folder) | `Listing = FindFirstFile`, 3 files, 114,688 bytes = sum of per-file allocation, `Exact` |

**Benchmark** (`WalkerBenchmarkTests`, 20,000 files in 401 folders, median of 5 walks after a warm-up,
run alone on the volume, administrator):

| Walker | Median | vs M0 |
|---|---:|---:|
| M0 (`FindFirstFileExW`, open every file) | 272.2 ms | 1.00x |
| v2 default (`FileIdExtd` listing + handle per file for streams) | 309.0 ms | 1.14x |
| v2 `--no-streams` (`FileIdExtd` listing + by-name query, no handle) | 116.4 ms | **0.43x** |
| v2 forced fallback (`FindFirstFileExW` + streams) | 307.9 ms | 1.13x |

All four give the same 20,000 files and 56,881,600 bytes. Counting alternate streams costs one extra
query per file, which is why the accurate default is a little slower than M0; without streams v2 is
2.3x faster than M0 (an earlier run: 494 / 625 / 193 / 631 ms, same ratios). The default stays
"streams on" for accuracy; `--no-streams` is there for whole-disk overviews.

### Safety (`Safety/SafetyGuard`, PLAN 4.4)

- Protected: the profile and every Known Folder from `SHGetKnownFolderPath` wherever it is redirected
  (25 folders resolved on the runner, including Camera Roll, Screenshots, Start Menu, per-user
  Programs), `AppData` and its three roots, `%LOCALAPPDATA%\Microsoft`, `\Packages`, `\Temp`, `%TEMP%`,
  the tool dot-folders (`.ssh .gnupg .aws .kube .docker .gradle .android .nuget` and a few more), every
  OneDrive root (shell folder, `OneDrive*` variables, each account's `UserFolder`, `OneDrive*` in the
  profile), the Scoop root, the dev roots and the quarantine roots. A protected folder and anything that
  contains one is refused; things inside are allowed.
- Allowed only strictly inside the profile (top-level only for dot-folders), a dev root or a quarantine root.
- One canonical path form: `\\?\` and `/` accepted, trailing separators trimmed, drive letter upper-cased;
  `..`, `.`, empty segments, trailing dots or spaces, `:` streams, wildcards, device and NT paths refused.
  Comparison is ordinal case-insensitive after 8.3 names are expanded with `GetLongPathNameW` (the
  runner's `%TEMP%` is `C:\Users\RUNNER~1\...`; the test folder's short form `...\DEVSWE~2\GUARD-~2\AFOLDE~1`
  resolves to its long path, and the short spelling of `%LOCALAPPDATA%\Microsoft` is still protected).
- No junction or link on the way (`ReparseGuard`); a volume mounted in a folder and a cloud-provider
  folder are not links and do not block, but the walker never crosses a mount and moves are same-volume.
- The item is opened as itself with DELETE access and `GetFinalPathNameByHandleW` (volume-GUID form)
  must give back the checked path; removal and quarantine then go through that handle, so a swap
  between check and act changes nothing (proved: the file renamed away after the check is deleted, the
  decoy put at its path survives). Recycling goes through the shell by path and is re-checked just before.
- Unit and property tests: 179 unit tests, including a fuzz of 50,000 random paths per run checked
  against an independent reference model, spelling-variant invariance, every protected path and each of
  its ancestors in five spellings, and `..` anywhere.

### Quarantine (`Platform/Quarantine`)

- Used when the Recycle Bin verdict is `WouldBePermanent`, `Unknown` or `NotAllowed` (path too long).
- Location: on the profile's volume `%LOCALAPPDATA%\DevSweep\Quarantine\<id>\<name>` (inside the profile,
  inheriting its user-only permissions); on any other fixed volume `<volume root>\DevSweep Quarantine\<SID>\<id>`,
  hidden and system, like `$Recycle.Bin\<SID>`: the root is the one folder every volume has and an item
  can only be renamed within its volume; the per-user folder gets a protected ACL (user, SYSTEM,
  Administrators) on NTFS/ReFS. Removable, network and optical drives have none.
- In: a rename by handle (`SetFileInformationByHandle(FileRenameInfo)`, never replacing, never copying;
  the same semantics as `MoveFileExW` without `MOVEFILE_COPY_ALLOWED`, but on the checked handle). A
  `<id>.json` manifest is written first. Out: exact restore, missing parents recreated, refused if
  anything now exists there or the way there became a junction. `List()` gives size and age; `Empty()` /
  `Delete(id)` delete for good.

| | Result |
|---|---|
| Folder with a hard link, 2 MiB | volume free space unchanged by the move (28,562,219,008 before and after); restore gives identical bytes, files, links |
| Empty two items (8 MiB + 4 KiB) | volume freed 8,392,704 bytes = the 8,392,704 quarantined |
| Item on the exFAT volume, quarantine only on C: | refused ("No quarantine folder is set up on this item's volume"), nothing copied; with a quarantine on that volume: moved and restored |
| 300+ character path | quarantined and restored |
| Default location | `C:\Users\runneradmin\AppData\Local\DevSweep\Quarantine\<id>\file.bin`, same volume serial |

### Blockers (`FileLocks`, Restart Manager)

`RmStartSession` / `RmRegisterResources` / `RmGetList` over every file of the item (batches of 500, up to
20,000 files; Restart Manager refuses paths of 260+ characters, so those use their 8.3 form or are
reported unchecked). With a child PowerShell holding a file open (no sharing): "Close Windows PowerShell
(powershell.exe, PID 4444) first; it has files in this item open." and nothing is touched. As a
**standard user in a batch logon, `RmGetList` returns `ERROR_ACCESS_DENIED`**; the check then probes each
file with an open for DELETE, which still finds the file in use ("Close the program using ... first")
but cannot name the process. DevSweep's own handle on the item is excluded.

### Cleaner and History (`Cleaning/`)

- The Mac model, ported: a plan of (Finding, CleanAction) gives `ActionOutcome`s. `Delete` only for
  `Risk.Rebuilds`; `Trash` to the Recycle Bin when it will really keep the item, otherwise the quarantine,
  and the outcome says which; `Command` runs argv with no shell, a time limit (process tree killed) and
  captured output; `Manual` changes nothing. Named blocker processes are re-checked first; every path
  goes through the guard and the whole action is refused if any path is refused (nothing changed).
- History: `%LOCALAPPDATA%\DevSweep\history.json`, source-generated JSON, atomic writes (temp file
  written through, then `ReplaceFileW` / `MoveFileExW`); an unreadable file is set aside, never
  overwritten. Each item records where it went: the Recycle Bin `$R` path and its `$I` record, or the
  quarantine path and ID. Restore from the Recycle Bin reads `$Recycle.Bin\<SID>\$I*` (format v1 and v2),
  renames `$R` back (same volume, no copy) and removes `$I`.
- Freed-space reconciliation after every clean (`GetDiskFreeSpaceExW` before and after, shown vs expected
  vs freed, tolerance 1% or 10 MB, recorded in the outcome and History). The Recycle Bin and the quarantine
  free nothing until emptied, so their expected value is 0.

| | Result |
|---|---|
| Delete a 64 MiB cache (with a read-only file and a junction to outside) | shown 67,112,960, expected 67,112,960, volume freed 67,112,960 (difference 0); junction target kept |
| Trash 256 KiB to the Recycle Bin, then History restore | landed as `C:\$Recycle.Bin\<SID>\$RX292OH.msi`; restored byte-identical, `$R` and `$I` gone; free space unchanged (expected 0) |
| Trash 3 MiB with a 1 MiB bin limit / with an unknown limit | quarantine, with the reason recorded; restored from History |
| Command | `findstr` with quotes, `&` and `|` in one argument passed literally; `ping -n 30` stopped at its 2 s limit; a missing program reported |
