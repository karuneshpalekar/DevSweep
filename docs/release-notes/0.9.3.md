DevSweep 0.9.3 fixes downloading repos that belong to an organization. Everything from 0.9.2 is included.

Requires macOS 14 Sonoma or later. Projects uses the GitHub CLI (`brew install gh`, then `gh auth login`).

## What changed

- **Organization repos download again.** Downloading a repo owned by an organization (or by an account you're not signed in to) failed with "no oauth token found for github.com account <org>". It now uses your active signed-in account, which is the login that has access, and the commit-identity note shows that account.
- **No cloning over existing files.** A download refuses to go into a folder that already has something in it, and says why.
- **Blocked folders are called out.** When macOS won't let DevSweep open a scan folder such as `~/Documents/GitHub`, the Projects list shows a banner with an **Open Privacy settings** button, instead of silently listing those projects as missing.

## Install

1. `brew upgrade --cask devsweep` (or `brew install --cask karuneshpalekar/tap/devsweep`), or download **DevSweep-0.9.3.dmg**, open it, and drag DevSweep to Applications. Replace the old copy if asked.
2. A downloaded build isn't notarized by Apple, so allow it once:
   - **macOS 14:** right-click DevSweep in Applications, choose **Open**, then **Open** again.
   - **macOS 15 and later:** try to open it, then go to System Settings, Privacy & Security, and click **Open Anyway**.
   - **Or in Terminal:** `xattr -dr com.apple.quarantine /Applications/DevSweep.app`

## Verify the download

```
shasum -a 256 DevSweep-0.9.3.dmg
```
