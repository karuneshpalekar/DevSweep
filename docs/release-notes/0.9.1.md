DevSweep 0.9.1 fixes how Projects reports and removes repos. Everything from 0.9.0 is included.

Requires macOS 14 Sonoma or later. Projects uses the GitHub CLI (`brew install gh`, then `gh auth login`).

## What changed

- **Untracked files are no longer "changed files".** A repo with only files git doesn't track now says "2 untracked files", and the panel names them.
- **No more phantom download.** A remembered entry under an old owner or org is hidden when the same repo is already cloned on this Mac. It used to appear as a second, missing project with a Download button.
- **Any project can be removed, with a warning.** If something isn't saved on GitHub (unpushed commits, uncommitted changes, untracked files, stashes, or no GitHub copy at all), removal still works, but a dialog opens every time and lists exactly what would be lost. The folder goes to the Trash and can be restored from History until you empty it. Fully backed-up projects keep the simple confirmation, and "Remove safe projects" still only touches those.
- **Remove buttons are actually red** now. Before, macOS drew them in plain black.
- **Projects loads faster to the eye.** What's on this Mac shows first, then GitHub's side fills in.

## Install

1. `brew upgrade --cask devsweep`, or download **DevSweep-0.9.1.dmg**, open it, and drag DevSweep to Applications. Replace the old copy if asked.
2. A downloaded build isn't notarized by Apple, so allow it once:
   - **macOS 14:** right-click DevSweep in Applications, choose **Open**, then **Open** again.
   - **macOS 15 and later:** try to open it, then go to System Settings, Privacy & Security, and click **Open Anyway**.
   - **Or in Terminal:** `xattr -dr com.apple.quarantine /Applications/DevSweep.app`

## Verify the download

```
shasum -a 256 DevSweep-0.9.1.dmg
```
